===== ideation-dashboard =====
usage: ideation-dashboard [-h] {generate,generate-and-open,create,edit,model-binding,gate} ...

`generate` + (later) `generate-and-open` action subcommands (plan "cli.py";
change task 3.3).

Path-agnostic argparse front-end: `--output`-style arguments, no baked-in
snapshot path (the aggregation nightly lane wires the committed path). The
`generate` subcommand (this wave, T006) regenerates the deterministic snapshot
from the working tree, writes it through the interactivity boundary, and
validates it against the pinned openxFactory validator. The `generate-and-open`
subcommand (T012, US2) will layer `serve.py` + browser open on top of the same
generation path.

Runnable both as a module (`python3 -m ideation_dashboard.cli`) and as a script
(`python3 scripts/ideation_dashboard/cli.py`); it self-inserts `scripts/` onto
the import path so the sibling `doc_health` package resolves either way.

positional arguments:
  {generate,generate-and-open,create,edit,model-binding,gate}
    generate            regenerate the deterministic snapshot
    generate-and-open   regenerate the snapshot, serve it locally, and open the browser
    create              scaffold a new header-compliant ideation doc and open it for editing
    edit                select-to-edit: launch the human's editor over a listed document
    model-binding       model-provider settings: list / add / edit / remove bindings, and hand a
                        credential to the broker
    gate                human-only gate console actions (US9): demote / ratify / edit-apply /
                        kickoff

options:
  -h, --help            show this help message and exit

===== ideation-dashboard gate =====
usage: ideation-dashboard gate [-h]
                               {demote,ratify,edit-apply,dispose-possible,kickoff,propose,promote-to-staging,research-brief,derive-possibles,create-project,edit-project,lens-save-recipe,lens-add-as-cluster,create-document,edit-document,open-pr,share-session,abandon-session,cleanup-abandoned-branch}
                               ...

positional arguments:
  {demote,ratify,edit-apply,dispose-possible,kickoff,propose,promote-to-staging,research-brief,derive-possibles,create-project,edit-project,lens-save-recipe,lens-add-as-cluster,create-document,edit-document,open-pr,share-session,abandon-session,cleanup-abandoned-branch}
    demote              reject a proposal back to staging (mechanized reverse transition); peer of
                        the executing dashboard route POST /actions/gate/demote, which PLANS and
                        RECORDS only — this command is the only surface that can also --execute
                        the recorded plan
    ratify              approve a proposal (write the ratification record + register update)
    edit-apply          apply a HUMAN-approved redline to a change document
    dispose-possible    dispose a pending_review ai-derived possible (accept / reject / defer)
    kickoff             dispatch a ratified change's next step (refused without ratification)
    propose             commission proposal authoring for a staging topic (add-propose-verb)
    promote-to-staging  commission a staging fragment for an ACCEPTED possible (add-wheel-action-
                        verbs)
    research-brief      commission a PRE-VERDICT evidence brief for a possible (add-wheel-action-
                        verbs)
    derive-possibles    commission a CLUSTER-SCOPED run of the possibles-derivation lane (add-
                        wheel-action-verbs)
    create-project      commission a project-register edit creating one project (add-project-
                        scoped-selection)
    edit-project        commission a membership edit of an existing project (add-opendox-project-
                        header)
    lens-save-recipe    save a keyword-lens recipe as a workbench manifest (add-lens-gate-verbs)
    lens-add-as-cluster
                        add a keyword-lens set as a pending_review human-seen cluster (add-lens-
                        gate-verbs)
    create-document     create a NEW header-compliant ideation document through the gate (create-
                        only, recorded; add-workbench-bullseye-and-create)
    edit-document       rewrite an EXISTING document inside the tile's branch session (session-
                        only, recorded, one commit; 007-workbench-branch-sessions)
    open-pr             push the tile's session branch and open (or update) its pull request into
                        the existing Merge-Master ritual
    share-session       commit the session's dirty thread sidecars and push the branch so a
                        colleague can resume the session (opens NO pull request)
    abandon-session     end the tile's branch session without saving, with the required reason
                        (recorded on `main`; the branch survives)
    cleanup-abandoned-branch
                        delete an ABANDONED session's surviving local branch after durable
                        retention release (human-invoked, never automatic)

options:
  -h, --help            show this help message and exit

===== ideation-dashboard model-binding add =====
usage: ideation-dashboard model-binding add [-h] --repo-root REPO_ROOT [--bindings BINDINGS] --id
                                            ID --label LABEL --provider PROVIDER --credential-ref
                                            CREDENTIAL_REF --auth-kind {api_key,oauth}
                                            --credential-approver APPROVED_BY --endpoint ENDPOINT
                                            --dialect {xfactory-prompt-v1}
                                            -- BROKER ARGV [-- BROKER ARGV ...]

positional arguments:
  -- BROKER ARGV        the broker invocation, as argv members, after a bare `--`. Placeholders
                        ('binding_id', 'label', 'provider', 'credential_ref', 'auth_kind',
                        'approved_by', 'endpoint', 'dialect') are filled from this binding's own
                        fields

options:
  -h, --help            show this help message and exit
  --repo-root REPO_ROOT
                        the checkout whose bindings are being read
  --bindings BINDINGS   the bindings document (default: <repo-root>/ideation/dashboard/model-
                        provider-bindings.yaml)
  --id ID               the binding's id
  --label LABEL         the label the model menu shows
  --provider PROVIDER   the provider name the broker takes custody for (the broker's declared
                        `--provider`)
  --credential-ref CREDENTIAL_REF
                        the reference the broker resolves; NEVER the credential itself
  --auth-kind {api_key,oauth}
                        the authentication kind the broker holds
  --credential-approver APPROVED_BY
                        the human principal who approved this credential; the broker requires one
                        at intake and records it on every grant
  --endpoint ENDPOINT   the provider endpoint this binding's minted token is presented at
  --dialect {xfactory-prompt-v1}
                        the request grammar that endpoint speaks
