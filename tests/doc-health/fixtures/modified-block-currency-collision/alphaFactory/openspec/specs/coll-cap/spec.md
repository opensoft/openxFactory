# coll-cap Specification

## Purpose
Canon AFTER the unsafe archive order was taken, twice, in the two basis forms.

## Requirements

### Requirement: Promoted by the unsafe order
This text reached canon from a MODIFYING change's block, promoted before the
sibling that ADDS it archived. Nobody reviewed it as an addition.

#### Scenario: The unsafe order was taken
- **WHEN** the modifying change archived first
- **THEN** the addition it rested on is still active

### Requirement: Promoted by the unsafe rename order
This text reached canon the same way, over a sibling that RENAMES another
requirement into the title rather than adding it.

#### Scenario: The unsafe rename order was taken
- **WHEN** the modifying change archived first
- **THEN** the rename it rested on is still active

### Requirement: Lawful rename source
The NEGATIVE CONTROL. A title canon carries and an active change is renaming
AWAY from — which is what a rename renames, and reporting it would report every
lawful rename in the corpus.

#### Scenario: The lawful rename case
- **WHEN** a rename names this title as its `FROM:` half
- **THEN** nothing is reported
