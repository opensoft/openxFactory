# Proposal: mod-own-rename-unpromoted

THE CARVE'S OTHER SIDE, and the fixture a widening of the self-referential
state to a carrier's own RENAME would fail on.

This change renames a title the promoted specification does NOT carry, so
`resolve`'s own-rename precedence — which requires the OLD name to be in canon —
does not fire, and the block reaches the pairing check with the carrier as the
only writer of the title. It is NOT self-referential: a `## RENAMED
Requirements` block carries a pair of TITLES, not a second text, so there is no
"two texts for one requirement" in it. It is UNDECLARED, and the finding names
the rename that put the title there.
