# modified-block-currency-pairing

SYNTHESIZED. Built by `govern-sibling-added-modified-deltas` (Speckit F1) for
the sibling-pairing finding class.

Every case below is a `## MODIFIED Requirements` block whose title the promoted
specification does NOT carry and an active sibling DOES add — the shape the
family's resolver returns as `pending`, and which until this packet was dropped
before any check looked at it. **NOTHING HERE COMPARES REQUIREMENT TEXT.** The
three comparison arms still do not run against a pending block; what is asserted
is the PAIRING.

Canon (`openspec/specs/pair-cap/spec.md`) carries exactly ONE requirement, and
it is there for the own-rename carve alone: a title canon carries resolves
`canon` and never reaches this check.

| change | state | why it is here |
| --- | --- | --- |
| `mod-undeclared` | undeclared | the corpus's own standing shape before the § 6 sweep: a real pairing, no marker |
| `mod-self` | self-referential | ADDS and MODIFIES one title, NO marker — one finding, and no undeclared one beside it |
| `mod-self-marked` | self-referential | the same, carrying a marker naming ITSELF, which cures nothing |
| `mod-wrong-basis` | misdeclared (basis) | names a change that neither adds nor renames to the title |
| `mod-carrier-basis` | misdeclared (basis) | names the CARRIER as basis over a block that is not self-referential — the exhaustiveness hole the narrowing would open |
| `mod-wrong-by` | misdeclared (`by`) | right basis, wrong author: FALSE provenance, and the case that PASSES on a classifier checking the basis alone |
| `mod-two-markers` | misdeclared (count) | one valid marker and one that adds nothing — exactly ONE finding, on a fact about the BLOCK rather than about whichever marker a loop reached |
| `mod-one-marker` | SILENT | the pair of the row above: the same valid marker, alone |
| `mod-no-reason` | misdeclared (reason) | the complete prefix and NO ` — ` separator, over a RATIFIED basis |
| `mod-empty-reason` | misdeclared (reason) | the twin: a separator and nothing but whitespace after it |
| `mod-no-reason-unratified` | misdeclared (reason) | THE ORDER'S OWN FIXTURE — prefix-only over an UNRATIFIED basis, reported on the reason ground and NOT undisclosed |
| `mod-undisclosed` | undisclosed | declared over a `draft` basis whose reason clause says nothing about it |
| `mod-headerless` | undisclosed | the basis declares no standing this reader can resolve, which is treated as not ratified |
| `mod-declared` | SILENT | the state this check exists to produce |
| `mod-disclosed` | SILENT | an unratified basis, disclosed by the word the form reserves |
| `mod-own-rename-unpromoted` | undeclared | THE CARVE'S OTHER SIDE — the carrier's OWN rename to the title, whose `FROM:` half canon does not carry, so the own-rename precedence never fires and the block is placed by the absence of a marker |
| `mod-rename-amend` | not of this class at all | the rename-and-amend shape promoted canon resolves under the OLD name — and its ONE dropped clause proves the comparison arms RAN |

The adders are `add-basis-ratified` (`ratified`), `add-basis-draft` (`draft`)
and `add-basis-headerless` (no lifecycle header at all).
