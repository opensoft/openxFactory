# Implementation Plan: openxwallet deprecation minor (P2.5)

**Branch**: `018-openxwallet-deprecation-minor` | **Date**: 2026-08-27 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `/specs/018-openxwallet-deprecation-minor/spec.md`

## Summary

Cut one deprecating minor contract bundle whose entire semantic content is a
statement about the future of eight already-registered artifacts. Three moving
parts, in dependency order:

1. **The statement** — each of the eight openxwallet rows in
   `contracts/manifest.yaml` gains one `relocating:` sibling mapping; the
   changelog gains the deprecating-minor section naming the removal version and
   the migration path; `docs/contract-versioning-policy.md`'s "Deprecations
   Currently In Force" list gains its entry.
2. **The observation** — `scripts/check-openxfactory-pin.py` learns to read the
   manifest AT THE CONSUMER'S PINNED COMMIT and emit a WARN-tier notice naming
   each relocating artifact with its target repository and tag, without touching
   its exit-code semantics or its existing four verdicts.
3. **The publication** — `contract_bundle_version` bumps and
   `contracts/releases/contract-v1.46.digests.yaml` is generated by the house
   tool over a surface that still contains all eight artifacts. The annotated tag
   is NOT created here.

Nothing is deleted, and no contract file's bytes change.

## Implementation approach (the parts worth deciding once)

### The `relocating:` shape

```yaml
    relocating:
      to: opensoft/openXwallet
      tag: wallet-v1.1
      since: contract-v1.46
```

Block-mapping form rather than flow form, matching every other nested structure
in the manifest. Placed as the LAST key of each row, after `consumption_rule`, so
no existing line moves and the row diff is pure addition. Three sub-keys only —
no `removal` / `removed_at` key, per FR-002 and `tasks.md` 5.2.

`since:` names the bundle from which the declaration is in force, which is this
minor. It is the one sub-key that moves if the bundle is renumbered at merge.

### Where the checker reads the manifest

At the CONSUMER'S PINNED COMMIT, out of the local openxFactory checkout's
history: `git -C <aggregation_root>/openxFactory show <pin>:contracts/manifest.yaml`.

Rationale: the question D5 poses is "does the bundle THIS DOMAIN PINS carry
relocating rows". The consumer's pin is a commit, so the manifest at that commit
is the bundle they actually consume — reading the working tree instead would
answer a different question (what the checkout happens to have now), and would
warn a consumer whose pin predates the marker. The script already resolves
`aggregation_root / "openxFactory"` for its ancestry test, so no new path
plumbing is needed.

Any failure to read — commit not present locally, file absent, unparseable YAML,
not a mapping — yields NO notice and no failure. Per the release-inventory
family's own doctrine, a question that could not be asked is not a finding.

### Keeping the existing contract intact

`classify(pin, pointer, is_ancestor)` is locked by four existing tests and is
**not modified** — not its signature, not its four return verdicts, not its
messages. The new behavior is three additions:

- `relocating_rows(manifest)` — pure; returns the ordered list of
  `(id, to, tag)` for every contract row carrying a `relocating:` mapping.
- `relocation_notice(rows, pin)` — pure; returns the WARN message string, or
  `None` when there are no rows.
- `manifest_at_commit(openx_root, commit)` — impure; returns the parsed mapping
  or `None` on any failure.

`main()` prints the pin verdict exactly as today, then prints the relocation
notice if there is one, then returns `1 if verdict == ERROR else 0` — the same
expression as today. An ERROR pin and a relocation notice coexist: both lines
print, the exit stays 1.

### The cut, mirroring the last one

`git log -S "contract-v1.45" -- contracts/` finds commit `2cd5fce5`, whose
`--stat` is the precedent: `contracts/CHANGELOG.md`, `contracts/manifest.yaml`,
`contracts/releases/contract-v1.45.digests.yaml`, plus the contract files that
changed. It touched **no README rows** and **created no tag**. This feature
mirrors that exactly, substituting the policy-doc list entry (the
`contract-v1.34` precedent for a deprecation) for the changed contract files.

Order matters: manifest + changelog + policy doc are edited FIRST, then the
inventory is generated LAST, because the inventory records the bytes of
`contracts/CHANGELOG.md`, `contracts/manifest.yaml` and
`docs/contract-versioning-policy.md` — all three are release-surface members.
