# roles-authority-model

## MODIFIED Requirements

### Requirement: An enrolled autonomous lane carries a one-edit kill switch

The model SHALL ensure that every enrolled candidate class can be returned to the human merge gate by A SINGLE REVIEWED EDIT TO THE ENROLMENT DECLARATION TOGETHER WITH ITS DECLARED TEST COMPANION — the set of conformance assertions that pin that enrolment, named beside the declaration in the reviewed declaration itself, so that the withdrawing pull request is landable against the repository's required checks — and that the withdrawal takes effect on the next evaluation, without redeploying, reconfiguring or otherwise touching any lane.

The declaration SHALL remain the switch. The enrolment SHALL be held in a reviewed, diff-visible declaration read from the base branch, and the model SHALL NOT accept a kill switch held in a value that does not appear in a reviewable diff: not a repository or organization variable, not a secret, not an environment setting, not a platform toggle, and not any store whose change leaves no reviewable record. A withdrawal SHALL therefore be visible in the declaration's history forever, and SHALL be a code-owner-reviewed act by construction.

The companion SHALL be declared, and the declaration SHALL be kept honest by a test. Where a class is enrolled, the assertions that pin that enrolment — every conformance assertion that fails when the class is withdrawn, INCLUDING any golden or snapshot artefact whose recorded value moves with the withdrawal — SHALL be named beside the enrolment in the same reviewed declaration; and a conformance test SHALL assert BOTH EQUALITIES, each MEASURED AGAINST THE CAPTURED DECLARATION IN A COMMITTED POST-WITHDRAWAL BASELINE: the declaration SHALL be read and RETAINED BEFORE the withdrawal is applied, since the withdrawal removes it from the tree in which the measurement is taken; and a scratch tree in which that class alone is withdrawn — its enrolment declaration and the companion declaration lines beside it removed, and nothing else — SHALL carry that withdrawal COMMITTED as the baseline before any measurement is taken, so that what is measured afterwards is only what the measurement itself changes. Against that baseline the test SHALL assert that the CAPTURED companion ASSERTIONS equal the set that actually pin the enrolment — the measured set being obtained by RUNNING THE COMPLETE PINNING SUITE WITH THE CONFORMANCE MODULE EXCLUDED BY ITS OWN PATH, a measurement INDEPENDENT OF THE DECLARATION so that a pinning assertion the declaration OMITS is still run and still enters the measured set — and that the CAPTURED companion ARTEFACTS equal what REGENERATING EVERY ARTEFACT IN THE ALLOWLIST TABLE actually produces, not only those the declaration names, so that an artefact that moves undeclared is caught by the same equality: THE SET OF (IDENTIFIER, PATH) PAIRS PRODUCED BY REGENERATING EVERY ALLOWLISTED ARTEFACT ONE TOOL AT A TIME FROM THE BASELINE SHALL EQUAL THE DECLARED PAIRS — each allowlisted tool run ALONE from the committed baseline, with the tree restored to that baseline before the next, so that EVERY PATH THE TOOL CREATED, MODIFIED OR DELETED, TRACKED OR NOT, is ATTRIBUTED to the identifier that produced it. THE INVENTORY FOR EACH TOOL SHALL BE THE FULL WORKING-TREE DELTA AGAINST THAT BASELINE — tracked modifications and deletions, UNTRACKED files, and IGNORED files alike, taken after the tool's run and before the tree is restored — and SHALL NOT be a comparison of tracked content alone, which would not see a new or ignored file at all; AN IGNORED PATH A TOOL PRODUCES SHALL COUNT AS PRODUCED and SHALL fail the equality when undeclared exactly as a tracked one does, so that a generator writing an undeclared output where version control does not look is caught rather than admitted; a DECLARED pair whose identifier did not produce that path SHALL fail even where another allowlisted tool produced it, an UNDECLARED pair produced by any allowlisted tool SHALL fail, and the equality of the bare path sets SHALL be a CONSEQUENCE of that pair equality rather than the check, since a comparison of the path union alone cannot detect an artefact bound to the wrong recording tool — no more and no less, in both directions. NEITHER MEASURED SET SHALL BE DERIVED FROM THE DECLARATION IT IS COMPARED AGAINST: a check that runs only what the declaration names cannot detect what the declaration omits, and self-invocation SHALL be prevented by excluding the conformance module BY ITS OWN PATH rather than by narrowing either inventory. Each such artefact SHALL be named by A NORMALIZED REPOSITORY-RELATIVE POSIX PATH CONTAINED IN THE CHECKOUT, and the check SHALL REFUSE THE DECLARATION AT CAPTURE IN TWO STAGES. FIRST A LEXICAL REFUSAL THAT TOUCHES NO FILESYSTEM AT ALL: the declaration SHALL be refused where the declared path is AN ABSOLUTE PATH, CARRIES ANY `..` SEGMENT, ANY `.` SEGMENT, A BACKSLASH, AN EMPTY SEGMENT, A TRAILING SLASH, OR ANY NON-POSIX SEPARATOR — this stage opening nothing, resolving nothing and consulting no metadata, so a hostile spelling is refused before the filesystem is consulted at all; and this set of refusal classes is STATED HERE NORMATIVELY AND REPEATED VERBATIM wherever else this packet states it, so that the refusal set is ONE set rather than a list per site. THEN, AND ONLY FOR A PATH THAT SURVIVES THAT STAGE, A CONTAINMENT CHECK: the path SHALL be RESOLVED, following symlinks, and the resolved result SHALL be required to lie under the repository ROOT'S OWN RESOLVED PATH; this stage MAY consult filesystem METADATA, since resolution necessarily does, but SHALL NOT OPEN OR READ THE ARTEFACT BEFORE CONTAINMENT HOLDS. A refusal at EITHER stage SHALL name the refusal class and the offending declaration, so that a pull-request-editable declaration can neither reach outside the checkout nor be compared in a non-canonical spelling. Each such artefact SHALL be regenerated by AN ALLOWLISTED RECORDING TOOL NAMED BY IDENTIFIER IN THE DECLARATION AND RESOLVED ONLY IN REVIEWED TEST CODE: the declaration SHALL carry a bare identifier and SHALL NOT carry a command, an argument or any other text that is executed; that identifier SHALL be resolved to a fixed invocation by a table held in the reviewed conformance test code and run without a shell; and an identifier absent from that table SHALL fail the check rather than be resolved or executed, so that an edit to the declaration can never introduce execution. The movement of an artefact SHALL be measured by that regeneration DELTA against the baseline and SHALL NOT be inferred from the failing assertions, an existence check, or any other proxy; that delta SHALL NOT be narrowed to the declared paths, nor to tracked content alone, so that a path no declaration names is caught rather than hidden; and an artefact whose regeneration identifier is not declared and resolvable SHALL NOT be declared at all, and therefore cannot form part of an enrolment's companion. The model SHALL NOT accept an enrolment whose withdrawal fails NO conformance assertion: the measured set for every enrolled class SHALL be non-empty, and an empty measured set is a failing check, never a vacuous pass. So a stale declaration in either half is a failing check rather than a discovery made at the moment the switch is thrown.

The model SHALL NOT accept an enrolment whose withdrawal, WITH THE DECLARED COMPANION APPLIED AND NOTHING ELSE, is not landable against the repository's required checks. APPLYING THE COMPANION SHALL MEAN re-targeting each declared assertion's EXPECTATION to the post-withdrawal tree — the assertion re-targeted rather than deleted, skipped or weakened, so that it keeps noticing the enrolments that remain — and regenerating each declared artefact by the allowlisted recording tool its own declaration names; and NOTHING ELSE SHALL MEAN no change outside the enrolment declaration, the declared assertions' files and the declared artefact paths. An enrolment that cannot be withdrawn by a landable pull request is not enrolled under a kill switch, however the declaration describes itself.

WHAT THIS REQUIREMENT DOES NOT DO IS LOOSEN THE PINNING, and that is the point of stating the companion rather than removing the assertions. The conformance assertions that pin an enrolment SHALL keep the property that the enrolment's departure is NOTICED: the model SHALL NOT accept, as a means of satisfying this requirement, a suite that derives the enrolled set from the enrolment declaration itself and therefore passes unchanged whether the class is present or absent. The companion is a DECLARATION of what must move, never a licence for nothing to move. For the same reason an enrolment that NOTHING pins does not satisfy this requirement: an empty measured companion is the enrolment nobody would notice leaving, so the model SHALL NOT accept it as a vacuous pass on two empty sets, and the enrolment is non-conformant for lacking a pinning assertion until one is added.

#### Scenario: Withdrawing an enrolment
- **WHEN** the owner removes a candidate class from the enrolment declaration AND applies exactly the companion declared beside that class — re-targeting those assertions and regenerating those artefacts — and nothing else
- **THEN** the repository's required checks pass on that pull request and the removal lands
- **AND** the next evaluation of a pull request of that class reaches no envelope decision at all — it is not a candidate, the evaluation exits as not-a-candidate, no approval is offered and no sticky comment is posted
- **AND** that pull request stays at the human merge gate, exactly as it would had the class never been enrolled
- **AND** the withdrawal is visible in the enrolment declaration's history forever

#### Scenario: A kill switch outside the diff
- **WHEN** an enrolment is proposed whose disabling is a repository variable, a secret, an environment setting or any other value that does not appear in a reviewable diff
- **THEN** the enrolment is refused
- **AND** the refusal names the reviewability of the switch as the ground

#### Scenario: The companion is declared beside the declaration
- **WHEN** a candidate class is enrolled
- **THEN** the conformance assertions that pin that enrolment are named beside it in the same reviewed declaration, including any golden or snapshot artefact whose recorded value moves on withdrawal, each such artefact named by a normalized repository-relative POSIX path contained in the checkout — any other path form being refused when the declaration is captured, by the requirement's own refusal set: first the LEXICAL refusal, which touches no filesystem at all, and then containment against the repository root's resolved path, made BEFORE THE ARTEFACT IS OPENED OR READ — and named together with the ALLOWLISTED IDENTIFIER of the recording tool that regenerates it, an identifier only the reviewed test code resolves to an invocation, never a command carried in the declaration
- **AND** a conformance test CAPTURES that class's declared companion from the declaration BEFORE any edit is made, then, in a scratch tree where that class alone is withdrawn and that withdrawal is COMMITTED as the baseline, asserts that the CAPTURED companion ASSERTIONS equal the set that actually pin the enrolment — measured by running THE COMPLETE PINNING SUITE WITH THE CONFORMANCE MODULE EXCLUDED BY ITS OWN PATH, never by running only what the declaration named, so a pinning assertion the declaration omits is still run and still measured — and that that set is not empty
- **AND** the same test, in that same tree, regenerates EVERY ARTEFACT IN THE ALLOWLIST TABLE — the whole table, not only the entries this class declared — ONE TOOL AT A TIME from that baseline, each by its own allowlisted identifier and with the tree restored to the baseline between runs, and asserts that the set of (IDENTIFIER, PATH) PAIRS the FULL WORKING-TREE DELTA AGAINST THAT BASELINE — every path that run created, modified or deleted, tracked or not, ignored files included — attributes to each identifier equals the CAPTURED companion ARTEFACTS as declared pairs — no more and no less, each delta taken over the whole tree rather than narrowed to the declared paths, and over tracked and untracked content alike rather than tracked content alone — so the artefact's movement is measured rather than inferred from the failing assertions, an artefact declared against the wrong recording tool is caught, and a regenerated path that no declaration names is caught
- **AND** a declaration that has gone stale in either half is a failing check rather than a discovery made when the switch is thrown

#### Scenario: An undeclared companion is a finding against the enrolment
- **WHEN** a withdrawal is proposed with the declared companion applied and nothing else, and a required check goes red through an assertion that the companion does not name
- **THEN** the enrolment is non-conformant with this requirement
- **AND** the finding is recorded against the enrolment and its declaration, never against the suite that caught it
- **AND** the remedy is to complete the declaration, never to relax the assertion that noticed

#### Scenario: An enrolment nobody would notice leaving is refused
- **WHEN** a class is withdrawn alone in the scratch tree and no conformance assertion fails
- **THEN** the conformance check fails
- **AND** the enrolment is recorded as non-conformant for lacking a pinning assertion, and the companion realization must add one before the class may stay enrolled
