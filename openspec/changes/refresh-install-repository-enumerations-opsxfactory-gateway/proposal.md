## Why

**A sixth install repository is mounted, and no promoted enumeration names it.**
`opensoft/OpsxFactory-Gateway-Install` was created 2026-10-06T23:30:16Z (private,
default branch `main`) as the dedicated install repository ruled by OpsxFactory's
`amend-task-bound-gateway-review-notes` R4 (a) on 2026-09-27 (opensoft/OpsxFactory#207
comment 5857749009): the runtime home of the Ops domain's task-bound agent
authorization gateway, which is the Ops domain's one MCP server. It was admitted
to the aggregation at `installs/opsxfactory-gateway-install` by opensoft/xFactory#567,
whose admission record is `docs/2026-10-06-opsxfactory-gateway-install-admission-record.md`
in the aggregation. Measured at xFactory
`main` `651dd5c9`, `installs/` carries TEN mounts. openxFactory's promoted
enumerations of install repositories name FIVE. The gateway is not among them.

**The rule that makes this a successor and not a surprise is already canon, and it
held.** *"Install-repository enumerations are an index with a named authority"*
requires the change that admits a further install repository either to refresh
every promoted enumeration or to name, by citation, the issue or packet that
will. xFactory#567 named #1259, and #1259 names this packet. The refresh is a
reviewed change because requirement and scenario text moves, and only an
openxFactory change can edit these files.

**What indexing the repository does, and what it does not.** Listing it adds it to
the same enumerations that list `Hermes-Install`, `Omnigent-Install`,
`Keycloak-Install`, `OpenXPKI-Install` and `OmniWorker-Install`. The list sentence
in *"Install repository scope"* states one scope for every name in it (install,
operations, backup, restore, upgrade, verification, and disaster recovery), so the
listing carries exactly that and nothing about WHAT the gateway is. Measured at
xFactory `main`, no `repo-boundary-governance` requirement fixes what the
gateway's repository owns or must not contain, and the repository itself reads
`implementation_status: repository-seed. No runtime and no manifests; nothing
deploys from here.` with the gateway's realization HELD. Authoring that
boundary is a different act and is not taken here (§ *What it does NOT change*).
