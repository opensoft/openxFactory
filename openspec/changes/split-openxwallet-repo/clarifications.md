# Clarifications

_Captured during proposal council review. These constrain the design._
_Generated by /opsx:propose council on 2026-08-26_

## Council-Identified Constraints

### Fail-closed refusals carry a remediation string
**Raised by:** Product Advocate
**Concern:** Every fail-closed refusal this change adds — an uninitialized submodule, a digest disagreeing with the pin — currently tells the operator that something is wrong without telling them what to run.
**Design impact:** `design.md` must fix the refusal message shape for every fail-closed path (`scripts/validate-trust-anchor.py` rule (f), the consumer gate's pin verify, openXwallet's vendored-schema verify): each refusal names `git submodule update --init --recursive openXwallet` and the path of `docs/pin-resync-runbook.md`, so the exit is in the message rather than in tribal memory.

### Emitter and shape of the manifest-carried `relocating:` marker
**Raised by:** Systems Architect / Adversary Engineer
**Concern:** P2.5's deprecation marker is ruled MANIFEST-carried rather than validator-carried, but neither the field's shape nor which tool warns on it is decided.
**Design impact:** `design.md` must fix the `relocating:` field shape on the eight rows at `contracts/manifest.yaml:1967-2082` (target repository, successor tag, and whether a removal version is required by `docs/contract-versioning-policy.md:247-249`'s CHANGELOG rule), and choose the emitter between the domain-pin checkers (`scripts/check-openxfactory-pin.py`, `scripts/validate-domain-openxfactory-pins.py`) and the release inventory — with the chosen emitter's warning output named as P2.5's evidence.

### Pin-digest verifiers in both directions, as running code
**Raised by:** Adversary Engineer
**Concern:** The pin exists on paper in both directions, but neither direction has a named verifier; openXwallet's `contract_pin.yaml` was given none, and openxFactory has no tool that checks the wallet pin's digests before the pinned reader runs.
**Design impact:** `design.md` must name and shape both — an openxFactory verifier (e.g. `scripts/verify-openxwallet-pin.py`) that checks `contracts/openxwallet-pin.yaml`'s per-file sha256 and `pinned_by_commit_only:` set before the consumer gate invokes the pinned reader, and openXwallet's `verify_pin`-equivalent for the vendored `contracts/schemas/hermes-job-envelope.schema.yaml` on openAvatar's `contract_pin.yaml:15-21` model. Both must be RUNNING CODE with their own realization-evidence rows, not obligations stated in prose.

### Mechanism for excluding the `openXwallet/` gitlink from the consumer gate's sweep
**Raised by:** Systems Architect
**Concern:** The consumer gate sweeps openxFactory's tree and will walk into the `openXwallet/` gitlink; a submodule's `.git` is a FILE, so the existing `.git` skip does not fire, and the vendored copy of the family would be swept as live records.
**Design impact:** `design.md` must choose between a skip set (add the gitlink directory name to the sweep's exclusions) and a scan scope (narrow the target passed to the pinned validator), and state which one keeps `check_register` reachable — the register read depends on the scan target being the openxFactory root, so narrowing scope must not silently disable the register check.

### SSH→HTTPS versus app-token `insteadOf` for the nested fetch, and how PASS/SKIP is pinned
**Raised by:** Systems Architect
**Concern:** `.gitmodules` uses `git@github.com:` and `github.token` cannot clone a second private org repository, so the nested submodule fetch needs a decision; and a silently skipped `tests/trust-anchor/` is indistinguishable from a passing one if only collection counts are pinned.
**Design impact:** `design.md` must choose between the house app-token + `git config --global url."https://x-access-token:$TOKEN@github.com/".insteadOf "git@github.com:"` pattern (`doc-health-reusable.yml:143-158`) and declaring the nested `.gitmodules` URL as `https://github.com/opensoft/openXwallet.git`, and apply the choice consistently to `pytest-suite.yml`, `openxwallet-consumer-gate.yml` and the two `doc-health-reusable.yml` init filters (`:154-158`, `:815-819`). It must also state HOW the PASS/SKIP counts are pinned in `pytest-suite.yml`'s header alongside the moved collection count at `:37`.

### Field shape for LedgerxFactory's declared wallet pin
**Raised by:** Product Advocate
**Concern:** P5b records a DECLARED wallet pin in LedgerxFactory's `stack.yaml`, but the block's shape is unspecified and the repo already has one pin convention to mirror.
**Design impact:** `design.md` must fix the block to mirror the existing `xfactory:` block's fields (repository, commit, tag, declared-at, and whether a `*_ref_type: commit` discriminator is carried), state whether it lives beside `xfactory:` or nested under it, and confirm that the re-pin tooling preserves it — `stack.yaml:18-19` already warns that "re-pin tooling must preserve this block; regenerating it away is a health finding".

### The test that pins the consumer gate's invocation and proves the register was read
**Raised by:** Adversary Engineer
**Concern:** `main()` runs `repo_scan` — and hence `check_register` — only `if args.path is not None` (`scripts/validate-openxwallet.py:2160`), so a required check invoked with the wrong target or no target goes green having opened no register, and no test in `tests/` currently references the workflow at all.
**Design impact:** `design.md` must specify the test: where it lives, whether it asserts on the workflow YAML's literal invocation string, on a log line naming `governance/review-authority/register.yaml` as read, or on a finding emitted by `check_register` — and it must make the ASSERTION positive (the register WAS read), not merely that the argument was present.

### openXwallet's manifest row for the vendored envelope schema
**Raised by:** Adversary Engineer
**Concern:** `shared-contract-ownership:142` requires all publisher markers together, and openXwallet will carry a `contracts/schemas/` directory holding one file it does not own; recording it as an owned member would be false, and omitting it leaves the marker test unmet.
**Design impact:** `design.md` must fix the row's exact fields in openXwallet's `contracts/manifest.yaml` — a CONSUMED member with `compatibility: canonical_openxfactory_contract`, `adapter_owner: openxFactory`, and a digest equal to the pinned openxFactory row's — and state how the wallet's own release tooling excludes a consumed member from `wallet-vN.M`'s release surface and its `digests.yaml`.
