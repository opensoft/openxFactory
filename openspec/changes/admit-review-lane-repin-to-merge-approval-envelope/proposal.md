## The design problem, confronted rather than routed around

**The ground that refuses this enrolment is not a preference. It is a comment in
codexFactory's floor document, at
`scripts/merge_master/openxfactory-review-authority-floor.yaml:108-111`,
attached to the entry `contracts/review-lane-pin.yaml`:**

> A fourth, separately grounded entry (not part of the wallet-register trio
> above): the review-lane pin selects which codexFactory commit's decision core
> judges this repository. Clearable, it would let a pull request choose its own
> judge.

**and it is composed OVER the envelope, in running code**, at this repository's
`.github/workflows/merge-master-approval.yml:1603`: `park "the candidate touches
the repository gate floor (matched=…); a never-clearable path is never
autonomously approvable, whatever the envelope says"`. It fires BEFORE the
envelope is consulted. It is also promoted-adjacent canon: the ratified
`extend-merge-master-envelope-to-floor-bot-lanes` `roles-authority-model` delta
adds *A never-clearable floor member is never autonomously approvable*, whose
second paragraph is the only door out and it is a narrow one — the permission
"SHALL be expressed as a CARVE naming the candidate and the exact member set it
may touch — never as the removal of the member from the floor".

### The answer: the pull request does not choose the judge, and cannot

**An enrolment does not make the pin clearable and does not give the pull request
a choice.** The candidate class binds four things the pull request has no degree
of freedom over, and each is a measurement rather than a promise:

1. **The author.** `expected_author: openxfactory[bot]`, measured (`gh api
   repos/opensoft/openxFactory/pulls/732 --jq .user.login` → `openxfactory[bot]`),
   with `expected_head_ref: bot/review-lane-repin` and `expected_base_ref: main`
   measured on the same pull request. A pull request from any other author, or on
   any other head, matches no class and parks.
2. **The diff.** It is produced by `scripts/review_lane_repin.py`, whose five
   sites are four files, which moves all five or opens nothing, proves the move
   by reading it back, and writes nothing outside them. `path_allowlist` names
   those four files EXACTLY — not a directory pattern — so a fifth path in the
   diff parks the candidate whatever else is true.
3. **The value.** `.github/workflows/review-lane-repin.yml:424-441` resolves
   codexFactory's default branch AT RUN TIME and refuses to pin at any other
   reference; the header at `:67-69` records that the lane "ignores any commit,
   branch or reference named by its trigger" and that the payload is never read.
   **So the only value this lane can ever propose is codexFactory's own
   default-branch head.**
4. **The judge is exercised on the candidate before the approval.**
   `pytest-suite`'s LQ-A7 freshness verifier
   (`tests/review_lane_pin/test_floor_snapshot.py::TheFreshnessVerifier`) runs
   against the core the pull request PROPOSES, not the superseded one, and it is
   a required check — so `require_all_checks: true` conjuncts it into the
   approval condition.

**Therefore the judge is chosen by the SOURCE FLOOR, not by the pull request.**
The choosing happened in codexFactory, when a commit landed on that repository's
default branch under that repository's own merge word. This repository's pull
request is the DELIVERY of that choice, and the enrolment approves a delivery
whose content is fully determined before the pull request exists. The floor
comment's hazard — a pull request choosing its own judge — requires a degree of
freedom this lane structurally does not have.

### The residual risk, stated rather than argued away

**It is real and it is one sentence: an autonomously approved delivery is the
envelope approving a change to its own NEXT judge.** Safeguards 1–4 bound WHICH
value can arrive; they do not make the arrival harmless if codexFactory's default
branch is itself compromised. What bounds that residual, and nothing more is
claimed:

* a human may close the pull request at any time, and the merge is still
  gated on every required check;
* the enrolment carries a one-edit kill switch — removing the class from
  `.github/merge-approval-envelope.yml` returns the lane to the human gate on
  the next evaluation, per the ratified *An enrolled autonomous lane carries a
  one-edit kill switch*;
* the CARVE is per-candidate and per-member, so `contracts/review-lane-pin.yaml`
  stays never-clearable for every other candidate and every other author, and
  `repository_floor_drift.py` continues to catch its removal;
* and the compromise this does not defend against — codexFactory's own default
  branch — is already the thing every hand merge of a re-pin trusts, because a
  human reviewer of #883 checked that forty hex characters matched codexFactory
  `main`, not that codexFactory `main` was sound.

**That last point is the honest core of the trade: the enrolment does not lower
the trust floor, it removes a human act that was never exercising judgement over
the trusted thing.** A reader who disagrees should refuse this packet, and
`design.md` D-1 (d) is written so that refusing costs nothing already spent.
