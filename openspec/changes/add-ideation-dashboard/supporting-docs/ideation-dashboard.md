## Problem

The family has a semantic surface over ideation content (the NotebookLM
projection) but no surface over its governance state: which topics exist at
which lifecycle stage, what each brainstorm could still become, which
possibles the organize gate picked, what is ready, blocked, or stale. That
state is scattered across doc headers, the staging INDEX, README lists, and
OpenSpec folders; assembling the picture means reading five or six files.
Two structural gaps surfaced during design: nothing records the candidate
feats ("possibles") a topic cluster could spawn but has not yet — unpicked
possibles evaporate into prose — and nothing lets a human assemble an
arbitrary doc set and point tools at it when they see a pattern the machine
clustering missed.

## Decided contract

1. **Projection, never a source of truth.** A generator scans `ideation/` +
   `openspec/changes/` (active and archive) and emits one schema-versioned
   snapshot (`kind: ideation-dashboard-snapshot`, `schema_version`);
   renderers only read the snapshot. If the dashboard disagrees with the
   repo, the dashboard is wrong and is regenerated.
2. **Realization funnel as primary view, six columns, docs first**: *source
   docs → topic clusters → possibles → staged picks → proposals → realized*,
   with explicit edges at every hop. Doc→cluster edges come from `Topics:`
   headers; cluster→possible edges from the possibles register; both hops
   are **many-to-many**. Per-cluster tallies count links, not cards. A
   five-column "collapse docs" mode remains for scale.
3. **Possibles register**: every topic cluster's candidate feats carry a
   state — `latent` (enumerated, unpicked — backlog, not failure), `picked`
   (citing the staged topic), `rejected` / `superseded` (with recorded
   reason and citation). Picks are the funnel's organize-gate edges.
4. **Workbench**: the user assembles a temporary **reference set** of docs —
   cluster-seeded (one click on a cluster card) or ad-hoc from the doc list —
   and points tools at it: scratch NotebookLM notebook (`xf-wb-<name>`),
   on-demand readiness scoring, scoped doc-health, and a *draft* organize-
   gate action that pre-fills a `staging/<topic>/` packet skeleton for human
   review. An ad-hoc set matching no machine cluster is treated as signal —
   a human-seen pattern proposed back to the cross-reference index.
5. **Boundary (permanent)**: non-mutating over source docs and never
   executes a gate. In scope: assembling reference sets, launching analysis
   tools, drafting gate artifacts. Out of scope forever: moving, editing,
   promoting, or deleting source docs; executing any stage transition.
6. **Secondary views** from the same snapshot: pipeline board (stage columns
   with possibles badges), doc list (assembly surface), lineage, readiness
   heat (consumes the cross-reference index), health overlay, stats strip.

## Required deltas and tests

- openxFactory contract change (`add-ideation-dashboard`):
  - snapshot schema (`ideation-dashboard-snapshot`) and workbench manifest
    schema (`ideation-workbench`), both `kind` + `schema_version`;
  - possibles-register contract: states, transition rules, reason/citation
    requirements (R2/R3), register home (R1);
  - `Possible feats:` addition to the brainstorm header/section format
    (MODIFIED `document-lifecycle`);
  - nightly snapshot lane (MODIFIED `doc-health`);
  - human-seen-cluster intake (MODIFIED `ideation-cross-reference`,
    sequenced with `add-ideation-cross-reference-readiness`);
  - the interactivity boundary as a normative requirement with scenarios.
- codexFactory realization delta: generator (deterministic — same tree,
  same snapshot), renderers (funnel/board/doc list from the mockup
  skeleton), workbench actions wired to `nlm`, scoped doc-health, and the
  readiness panel once it lands.
- Tests: snapshot and manifest schema validation; register transition
  validation (rejected/superseded without reason+citation fails);
  determinism check; boundary test (generator and workbench actions write
  only under their own output paths); funnel fixtures from the R4 backfill.
