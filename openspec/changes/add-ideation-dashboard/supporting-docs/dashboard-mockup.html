Illustrative design mockup, populated by hand from the repo state at 2026-07-12. The workbench tray and authoring buttons are mocks: they describe what they would run (scratch NotebookLM notebook, on-demand readiness, scoped doc-health, organize-gate draft, scaffolded doc creation, editor launch) — none execute here. Authority split: humans create and edit docs; agents only create; the dashboard's own machinery never modifies a source doc, and no one executes a gate through it. Cluster↔possible links are many-to-many: one doc's Topics: list feeds several clusters, and one possible can be claimed by several clusters (dashed violet edges). Possibles are inferred from prose — no possibles register exists yet, which is precisely the gap the funnel exposes: the real dashboard can only render what a register declares. Data source in the proposed design: a generated dashboard.json snapshot (headers, staging INDEX, cross-reference readiness index).
