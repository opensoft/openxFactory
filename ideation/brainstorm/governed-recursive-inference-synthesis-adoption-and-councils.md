## Possible feats

- **Recursive adoption readiness profile** — evaluate runtime, task, safety,
  evidence, economics, and domain-review readiness before activation.
- **Council-ready recursive assurance packet** — give independent Hermes
  reviewers the same bounded, cited evidence and preserved dissent inputs.
- **Cross-domain pilot ladder** — codexFactory first, then selectively qualify
  OpsxFactory and LedgerxFactory, with MedxFactory last and decision-support
  only.

### Placement keeps adoption from changing authority

The [placement decision](governed-recursive-inference-placement.md) remains the
same across domains: recursive inference is an Omnigent execution strategy,
not a Hermes decision role. This allows adoption thresholds to vary without
changing the authority stack.

codexFactory may use a recursive verifier for a repository corpus; MedxFactory
may later use a recursive evidence assembler for a patient timeline. Neither
worker merges code, signs an order, writes canonical truth, or approves itself.

### Routing makes activation task-specific

A domain does not "turn on RLMs" generally. It registers particular task
classes whose [strategy route](governed-recursive-inference-strategy-routing.md)
has evaluation evidence:

```text
task class
  + corpus class
  + data/sensitivity class
  + quality and coverage band
  + runtime/topology profile
  + baseline evidence
  = activatable recursive route
```

An unregistered or ambiguous task falls back or escalates.

### Budgets separate experimentation from production

The [budget and depth profile](governed-recursive-inference-budget-and-depth-control.md)
can define an experimental lane with small public/synthetic corpora and a
governed lane with reviewed ceilings. A domain-specific success result does not
authorize deeper recursion or higher spend in another domain.

### Coverage and safety define domain readiness

The [coverage](governed-recursive-inference-evidence-coverage.md) and
[safety](governed-recursive-inference-safety-and-data-boundaries.md) thresholds
tighten with consequence:

| Domain posture | Leading proof pressure |
| --- | --- |
| codexFactory | seeded correctness, repository coverage, sandbox escape, cost |
| OpsxFactory | secret handling, volatile evidence, action separation |
| LedgerxFactory | complete item coverage, numeric tool separation, confidentiality |
| MedxFactory | consent, PHI disclosure, source authority, clinician decision |

The mechanism remains neutral; the domain overlay owns the specialized source,
evidence, validation, and review content.

## Council integration

### Preferred early pattern: recursive evidence compiler before council

```text
Hermes-approved review job
  -> recursive Omnigent evidence compiler
  -> assurance packet
  -> independent council reference agents
  -> acting Hermes synthesis
  -> Hermes/human gate
```

Benefits:

- one governed large-corpus access path;
- all reviewers see a comparable packet;
- coverage and exclusions are visible;
- council disagreement focuses on interpretation rather than unknown corpus
  navigation differences;
- recursive execution remains Plane-2 work.

### Later experiment: independent recursive reference paths

Giving each council member its own recursive exploration may reveal different
evidence and reduce common-mode selection bias. It also multiplies cost and
disclosure, creates different coverage sets, and complicates dissent analysis.

If explored, each reference path needs its own task family and coverage ledger
under one council context policy. The council evidence must preserve which
reviewer saw which corpus subset.

### Acting Hermes use

The acting role might use recursive context computation to inspect very large
reference outputs, but it should produce a recommendation and separate gate
decision. Mixing adaptive execution and decision authority in one opaque trace
would weaken the existing MoA boundary.

## Adoption readiness dimensions

A task class might be reviewed across:

1. **Problem fit** — large/irregular context and genuine adaptive need.
2. **Authority fit** — existing worker archetype and permission boundary.
3. **Runtime fit** — sandbox, capsule, combinators, child templates.
4. **Safety fit** — data classes, providers, egress, injection, retention.
5. **Evidence fit** — claims, coverage, trajectory, replay, validation.
6. **Economic fit** — better cost/quality than simpler strategies.
7. **Operational fit** — scheduling, rate limits, observability, incident
   response.
8. **Review fit** — domain verifier, challenge, Hermes/human gate.

Readiness could be a packet and review process without becoming a universal
numeric score.

## Emergent behavior

The adoption cluster makes recursive inference an evidence-earned domain
capability rather than a library rollout:

- codexFactory can prove the runtime on low-sensitivity real work;
- task-specific routes prevent indiscriminate activation;
- councils receive a structured evidence product;
- higher-risk domains reuse the neutral mechanism while adding stricter
  profiles;
- failure in one domain/task/topology does not invalidate all recursive
  inference;
- no pilot result grants terminal or cross-domain authority.

## Tensions to hold

- Starting with real xFactory work improves relevance but makes ground truth
  harder than synthetic benchmarks.
- One shared evidence compiler improves comparability but creates common-mode
  evidence-selection risk.
- Independent council exploration improves diversity but multiplies cost and
  disclosure.
- A formal readiness score aids routing but may imply false comparability
  across domains.
- Medx use is potentially valuable for longitudinal evidence but carries the
  strongest reason to wait.

## Recombination opportunities

- Combine recursive assurance packets with the existing Hermes council modes.
- Route repeated, stable recursive task families into the pattern-ledger and
  crystallization funnel.
- Use codexFactory to build and validate typed runtime/combinator capabilities
  that other domains consume through overlays.
- Add domain-specific sentinels to capability-health after any recursive route
  reaches a stable governed state.

## Open questions

- Which codexFactory task should be the forcing pilot?
- Does council use belong in the first pilot or only after standalone
  evidence-compilation success?
- What evidence threshold allows a task route to move from experimental to
  governed?
- Which cross-domain findings can be reused without leaking tenant or subject
  data?
- Should Medx require a separate high-assurance conformance profile or simply
  stricter domain policy over the same neutral contracts?
