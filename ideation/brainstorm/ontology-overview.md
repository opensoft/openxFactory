## Possible feats

- **xFactory semantic execution kernel** — a versioned ontology, context
  compiler, routing interface, and maintenance evidence loop.

## Motivation

xFactory currently carries meaning across prose, schemas, worker prompts, and
domain conventions. Exact-string routing and broad context assembly cannot
reliably express when two tasks are semantically equivalent, which policies
apply, or why a worker and evidence set were chosen.

## Goals

- Give concepts and relations stable, provenance-bearing identities.
- Compile minimal task context with an explanation of inclusion.
- Route micro-agents through declared semantic requirements.
- Reuse context and results only under compatible meaning and authority.
- Turn observed drift into reviewable maintenance proposals.

## Non-goals

- The brainstorm does not select an ontology storage engine.
- It does not make an ontology agent a policy or domain authority.
- It does not claim all natural-language ambiguity can be eliminated.
- It does not authorize cross-tenant semantic leakage.

## What the system delivers

The proposed system produces a pinned semantic-context packet for each task,
eligible worker and tool constraints, cache compatibility evidence, and
maintenance observations. Each result can identify the ontology revision and
context decisions that shaped it.

## System model

```text
versioned ontology
  → task/context compilation
  → bounded worker routing
  → governed execution and result
  → cache/evaluation evidence
  → maintenance proposal
  → authority review
  → new ontology revision
```

## How it fits

The ontology is a proposed semantic layer, not a replacement for OpenSpec,
Hermes authority, tenant consent, or Omnigent enforcement. Domain ontology
generation and maintenance remain separately governed, while the neutral
layer defines portable identities and execution interfaces.

## Key decisions and open questions

The load-bearing decision is whether semantic context becomes a pinned
execution artifact rather than hidden prompt assembly. Open questions remain
around storage, revision compatibility, domain ownership, and the minimum
explanation safe to retain.
