## Possible feats

- **Constrained autonomous implementation loop** — require pre-edit admission, independent evidence, Project Owner acceptance, and Merge Master readiness without a human checkpoint for every routine change.
- **Authority and exception ledger** — link delegated agent decisions, protected gates, overrides, preview outcomes, annotation cleanup, and follow-up observations to one intent lineage.

### Authority is distributed, not implied by a green check

The original user owns what they actually said in an annotation; Project/Subject Hermes owns project-specific product management under its approved constitution and authority envelope. The Project Owner decides user-visible acceptance, the Project Manager owns sequencing and disposition, specifications supply constraints, specialists propose and review, test runners provide evidence, and Merge Master governs final enforcement. None of these roles should silently stand in for another.

### Safety is an admission boundary

The spec-aware check belongs before implementation because a later passing test cannot prove that an unsafe behavior was allowed. Unknown or stale specifications should be visible as reduced assurance, not converted into a pass. Overrides should be narrow, attributed, reasoned, authority-bound, and reviewable. The ordinary UI lane cannot weaken the constraints or policy by which it is judged.

### Preview is an integration and feedback boundary

The preview makes the exact verified revision available for final synthetic journeys and optional user review. It creates a safe place for a user to say “this interpretation is wrong” and add a new annotation without making that user the mandatory manager of every session. Project Hermes may admit an in-envelope preview; protected or directly contested outcomes park at the authority named by policy.

### Merge is an explicit authority transition

The [V1 SDLC Session Protocol](agent-assisted-app-testing-v1-sdlc-session.md) separates proposal admission, implementation, verification, experience admission, merge readiness, and external enforcement. Project Hermes acceptance does not itself grant a Git capability; Merge Master and configured Git/CI rules remain separately auditable and linked to the exact reviewed revision.

### Runtime pixels need a named authority

The [Approved UI Source of Truth](agent-assisted-app-testing-approved-ui-source.md) separates repository-owned runtime snapshots from the project UI constitution, specs, design-tool context, specialist interpretation, Subject Hermes admission, and merge enforcement. This prevents a Figma frame, a green test, or one model opinion from silently becoming the accepted browser rendering.

The [Hermes Designer Visual Review](agent-assisted-app-testing-hermes-visual-review.md) makes a visual specialist useful without granting it baseline authority: it can classify a diff and prepare a candidate update, while the Experience Council, Project Owner, Merge Council, and Merge Master preserve role-separated admission.

### Humans are exception authorities, not routine managers

The [UI Change Autonomy Envelope](agent-assisted-app-testing-ui-autonomy-envelope.md) allows routine regression repairs and bounded experience improvements to complete through agent authorities. Humans or accountable professionals remain at ratification, protected/regulated decisions, novel product meaning without adequate authority, irreconcilable contested findings, and external enforcement surfaces that are structurally human-gated. Stable out-of-envelope work parks with a decision-ready packet; it does not interrupt a person merely because a test failed or an agent is uncertain.

## Emergent behavior

The combined system supports genuine bounded autonomy: Project Hermes can manage routine reproduction, implementation, review, baseline admission, and merge handoff without waiting for a person at every step. Explicit constraints, separated roles, deterministic evidence, Product Owner acceptance, and Merge Master enforcement prevent a technical pass from becoming an unauthorized product change. Re-annotations and proactive observations become linked iterations rather than disconnected reports.

## Tensions to hold

- Strict blocking improves safety but can turn missing documentation into a constant bottleneck.
- Broad Project Hermes authority enables unattended repairs but increases reliance on a current constitution, qualified agents, and trustworthy policy classification.
- Early annotation deletion makes the interface cleaner; delayed resolution makes pending Project Hermes or protected-gate judgment visible.
- Hosted previews reduce friction but increase concerns about secrets, identity, data isolation, and retention.
- Faster baseline maintenance conflicts with the need to preserve old profile identities and make rendering migrations reviewable.
- Keeping humans out of routine management conflicts with the need to prevent agents from quietly changing their own tests, thresholds, or authority envelope.
